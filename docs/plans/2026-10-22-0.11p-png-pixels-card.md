## Contract: src/core/assets/png-pixels.ts
- `export class PngPixelError extends Error` with `readonly code` set to one of: 'signature', 'chunk', 'crc', 'header', 'unsupported', 'zlib', 'inflate', 'adler', 'filter', 'size', 'limit'.
- `export interface PngPixelLimits { maxWidth: number; maxHeight: number; maxPixels: number; maxInputBytes: number }`. Defaults: 16384, 16384, 16777216, 67108864.
- `export function decodePngRgba8(bytes: Uint8Array, limits?: Partial<PngPixelLimits>): { width: number; height: number; rgba: Uint8Array }`.

Behaviour, in order:
1. Input length at most maxInputBytes, else 'limit'. Signature: the first 8 bytes are 89 50 4E 47 0D 0A 1A 0A, else 'signature'.
2. Chunks: length (u32 big-endian), type (4 bytes), data, CRC (u32 big-endian over type and data, via crc32 from png.ts). A length that runs past the input gives 'chunk'. A CRC mismatch gives 'crc'. The first chunk must be IHDR of length 13, else 'header'. Exactly one IEND, and it is the last chunk, else 'chunk'. An unknown ancillary chunk (first letter lowercase) is skipped. An unknown critical chunk (first letter uppercase, other than IHDR, PLTE, IDAT or IEND) gives 'unsupported'.
3. IHDR: width and height are integers from 1 to 2147483647. width at most maxWidth, height at most maxHeight, and width times height at most maxPixels, else 'limit'. Bit depth must be 8, else 'unsupported'. Colour type must be 0, 2, 3, 4 or 6, else 'header'. Colour type 3 needs a PLTE chunk of 1 to 256 entries, else 'header'. Compression method 0 and filter method 0, else 'header'. Interlace method 0, else 'unsupported'.
4. tRNS: colour type 3 gives one alpha byte per palette entry (255 for entries not listed). Colour types 0 and 2 give a colour key (2 bytes for gray, 6 bytes for RGB, big-endian): pixels whose 8-bit samples match the key get alpha 0. Colour types 4 and 6 ignore tRNS. A tRNS chunk of the wrong length gives 'header'.
5. The IDAT chunks, concatenated in order, form one zlib stream. No IDAT gives 'chunk'.
6. zlib: CM = 8 and CINFO at most 7; (CMF times 256 + FLG) mod 31 = 0; FDICT clear. Otherwise 'zlib'.
7. DEFLATE per RFC 1951: stored blocks (LEN and NLEN checked), fixed Huffman codes, dynamic Huffman codes (HLIT at most 286, HDIST at most 30). Block type 3 gives 'inflate'. Reading past the input gives 'inflate'. An over-subscribed code gives 'inflate'. An incomplete code is accepted only where RFC 1951 allows it. A distance beyond the start of the output gives 'inflate'. Output may never exceed the expected size, height times (1 + width times channels), else 'size'. Channels: colour 0 gives 1, colour 2 gives 3, colour 3 gives 1, colour 4 gives 2, colour 6 gives 4.
8. After the final DEFLATE block, the Adler-32 (4 bytes, big-endian, over the uncompressed data) must match, else 'adler'. Bytes after the Adler-32 give 'zlib'. The output size must equal the expected size exactly, else 'size'.
9. Unfilter each row. Filter byte 0 to 4 (None, Sub, Up, Average, Paeth, per the PNG specification). Any other value gives 'filter'. Byte arithmetic is mod 256. Bytes left of the row start count as 0. For the first row, the "up" bytes are 0.
10. Expand to RGBA8: colour 0 gives (g, g, g, 255), or alpha 0 on a key match. Colour 2 gives (r, g, b, 255), or alpha 0 on a key match. Colour 3 gives the PLTE colour with its tRNS alpha; an index past the palette gives 'header'. Colour 4 gives (g, g, g, a). Colour 6 is copied as stored.

Performance: linear in the output. No recursion. Every loop is bounded by the input or the output size.

## Tests: tests/unit/assets-png-pixels.test.ts (vitest)
- Build synthetic PNG files inside the test with a small test-only encoder. Compression may use node:zlib, which is allowed in tests. Expected pixels are invented values written out by hand. Do not call decodePngRgba8 to compute an expected value.
- Each case is one `it`:
  1. RGBA 2x2, stored (level 0): four distinct colours, one with alpha 0 and one with alpha 255.
  2. RGB 3x1, deflate level 9: exact.
  3. Gray 4x1: each output is (g, g, g, 255). With a colour key set to one value, only that pixel gets alpha 0.
  4. Gray+alpha 2x1: exact.
  5. Palette 2x2 with a 3-entry PLTE and a 2-entry tRNS: exact. An index past the palette gives 'header'.
  6. Filters 0 to 4, one per row, on a 4x5 RGB image: exact. The test encoder applies each filter, and the decoder recovers the source pixels.
  7. Dynamic Huffman: 64x64 RGBA of seeded pseudo-random content, deflate level 9: exact round trip.
  8. Fixed Huffman: a hand-built stream that encodes one short literal run, with its bit sequence written in the test. If the bit sequence cannot be verified, report the case as NOT COVERED instead of passing it.
  9. Errors, each with its code: bad signature ('signature'); flipped CRC ('crc'); IHDR not first ('header'); missing IEND ('chunk'); bit depth 16 ('unsupported'); interlace 1 ('unsupported'); colour type 5 ('header'); filter byte 5 in a row ('filter'); flipped Adler-32 with the IDAT CRC recomputed, so only the Adler check fails ('adler'); truncated IDAT ('chunk' or 'inflate'; the call returns); an IDAT whose output is larger than the header allows ('size'); width above maxWidth ('limit'), refused before inflate.
  10. No hang: after a valid IHDR, 10,000 seeded random bytes as IDAT return an error (any code) inside the test timeout.
