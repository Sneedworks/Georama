# 0.11p correction 2 (public)

Correction by addition to the 0.11p PNG pixel decoder. The record is published with the code it describes.

- NaN limit values (maxWidth, maxHeight, maxPixels, maxInputBytes) throw PngPixelError with code `limit` and the message `Invalid limit value`. The check runs on the floored values, so a non-number that converts to NaN is rejected as well.
- Both header-sized allocations (the expected output and the RGBA buffer) go through one helper that maps RangeError to code `limit`. A unit test reaches the second site with a small image and a stub on the global Uint8Array, restored afterwards.
- `+Infinity` limits remain "no explicit cap". A unit test pins that with an image wider than the default cap.
- Known residual, unchanged by this commit: a BigInt or Symbol limit still throws an untyped TypeError from Math.floor. It is fail-closed.
